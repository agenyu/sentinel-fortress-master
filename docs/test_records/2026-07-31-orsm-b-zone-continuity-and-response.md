# ORSM B区连续报警与状态反馈修复记录

日期：2026-07-31

## 1. B区问题与验证结果

测试数据为`b区.rsclbag`。修改前，人员位于B区时会因跨相机切换、短时视觉丢失和
LiDAR局部搜索回吸背景而出现报警中断、目标ID切换：

- 680个状态周期中，294个周期正常输出B区二级报警；
- 142个周期仍处于WARNING，但`intruders_info`为空；
- 共出现ID 1、2、5。

修改后：

- 680个状态周期中，前86个周期尚未确认目标；
- 第87～680周期连续输出B区二级报警，共594个连续报警周期；
- 目标距离6.14～11.93 m，始终保持ID=1；
- 最大相邻位置变化0.321 m，无大于0.35 m的位置突跳；
- 2700帧处理过程中无同步超时、同步缓存溢出或帧队列溢出。

## 2. B区修改内容

1. LiDAR-only动态目标延续总时长改为15秒，并从最后一次真实相机确认时间计时，
   避免LiDAR逐帧刷新`last_seen`导致延续永不过期。
2. 保存最近一次已确认的动态运动时间，使人员转弯或短时间位移不够直时不会立即失去
   动态语义。
3. 动态语义最低置信度由0.55调整为0.50，与全局轨迹准入阈值一致。
4. 跨相机ReID使用最后相机确认时间计算空间门限，最大匹配年龄调整为15秒。
5. 增加独立的原始LiDAR搜索锚点。对外位置继续按2 m/s和单步0.35 m限速，
   下一帧LiDAR搜索则从最新原始观测继续，避免回吸旧背景。
6. 重复轨迹合并时同步动态运动记忆和LiDAR搜索锚点；释放静态语义时清理动态记忆。
7. 生产配置继续关闭跨相机ReID，待多人、交叉和相似衣着场景验证后再开启。

## 3. 当前ORSM报警逻辑

### 3.1 模式与状态

- 未请求堡垒模式时为OFF。
- 单车请求路由到单车安防；多车请求路由到多车联防。
- 满足电源、P挡、SOC、驻车、故障等进入条件后由OFF进入ACTIVE。
- 最近5次评估中至少3次确认威胁，由ACTIVE进入WARNING。
- WARNING最少保持3秒，并要求连续5帧无威胁后才解除回ACTIVE。
- 退出条件或故障分别进入OFF或FAILURE。

### 3.2 单车区域

- C区：距离不大于5 m，三级报警。
- B区：距离大于5 m且不大于15 m，二级报警。
- A区：距离大于15 m且不大于30 m，一级报警；单目标远离本车时不报警。

报警主体必须是稳定的人/动物全局轨迹。相机提供语义，LiDAR提供距离、存在性和
跨视野连续跟踪；输出前还会执行多帧确认、空间去重、ID稳定、位置限速及短时保持。

### 3.3 多车区域

- 只监控配置的安防侧。
- 5 m内为不报警区。
- 5～15 m为内部区二级报警。
- 15～30 m为外部区一级报警。
- 还必须满足组队完成、IVI准备、链路就绪、静止时间和外部锁车等多车进入条件。

### 3.4 `/network/fortress_resp`反馈

`OrsmSettingStFb`当前反馈约定：

- 0：未请求堡垒；
- 1：单车安防成功进入；
- 2：多车联防成功进入；
- 3：已经请求开启，但ODD或多车组队条件不满足。

多车请求但组队条件不满足时，内部状态仍可为OFF，但对外必须返回
`OrsmSettingStFb=3`，同时`OrsmMessageRem=0xA`。
