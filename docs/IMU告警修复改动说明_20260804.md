# IMU 告警修复改动说明

## 1. 基本信息

- 改动日期：2026-08-04
- 项目目录：`/home/zhangweiyang/文档/0804/sentinel-fortress-master`
- 改动目的：修复实测摇晃包无法正确触发 IMU 告警的问题，同时抑制 5 m、15 m 和车外30 m静止包的振动误报。
- 修复结果：摇晃包能完成 `ACTIVE -> WARNING -> ALARM` 状态闭环，对照包未产生 IMU 告警。

## 2. 原问题说明

### 2.1 阈值与实测数据不匹配

旧代码直接判断单帧水平加速度和角速度绝对值：

```text
accel_xy > 2.0 m/s² OR gyro_magnitude > 0.5 rad/s
```

实测摇晃包的 Gyro RMS 主要在 `0.0027~0.0079 rad/s`，旧角速度阈值高约两个数量级，因此无法触发。

### 2.2 IMU 时间戳回退

五个包中的 `actualTimeNs` 均有周期性非单调问题：

- 0801 数据约回退 `100~110 ms`。
- 0724 数据约回退 `60 ms`。

旧实现用它直接计算 2 s 锁存时间，回退后锁存时长不可靠。

### 2.3 IMU 事件可被相机帧覆盖

IMU 约为 100 Hz，但威胁管理只在四相机同步组完成时评估。旧代码每到一路相机都直接覆盖 `pending.imu`，最后一路普通样本可能覆盖前面已捕获的振动样本。

### 2.4 冲击判定使用了错误的差值

旧代码计算了 `delta_accel_xy`，实际判定却使用三轴 `delta_accel`，姿态变化引起的 Z 轴重力分量可带来误报风险。

### 2.5 停机统计被清零

`main.cpp` 原来在 `node.stop()` 释放 IMU 订阅器后才读取统计，导致结束日志显示 `vibrations=0`，与运行期间的真实事件不一致。

## 3. 核心算法改动

### 3.1 高通滑波与滑窗 RMS

振动判定改为在 IMU 100 Hz 回调内完成：

1. 应用 IMU 标定补偿。
2. 用一阶 2 Hz 高通去除重力、固定偏置和慢速姿态变化。
3. 计算 500 ms 窗口内的三轴加速度 RMS 和三轴角速度 RMS。
4. 超阈持续 300 ms 后才确认事件。
5. 确认后锁存 3000 ms，避免低频相机评估错过 IMU 事件。

### 3.2 默认阈值

```yaml
imu_highpass_cutoff_hz: 2.0
imu_rms_window_ms: 500
imu_vibration_min_duration_ms: 300
imu_vibration_latch_ms: 3000
imu_accel_rms_threshold: 0.14
imu_gyro_rms_threshold: 0.0015
imu_accel_severe_rms_threshold: 0.20
imu_gyro_severe_rms_threshold: 0.0040
imu_accel_guard_rms: 0.04
```

一般振动：

```text
accel_rms >= 0.14
OR
gyro_rms >= 0.0015 AND accel_rms >= 0.04
```

严重振动：

```text
accel_rms >= 0.20
OR
gyro_rms >= 0.0040 AND accel_rms >= 0.04
```

加速度与静止机械振动存在重叠，因此使用 Gyro RMS 作为主要区分特征，Accel RMS 作为能量门限。

### 3.3 时间戳修复

- 保留原始 `actualTimeNs` 到 `raw_timestamp_ns`。
- 相邻间隔在 `2~30 ms` 内时使用原始间隔。
- 间隔超出范围或时间回退时，使用 10 ms 默认周期生成单调时间。
- 通过 `timestamp_fallback` 和累计日志保留诊断信息。

### 3.4 事件去重

一段连续摇晃只计为一个 IMU 事件。只有在 RMS 回落且 3 s 锁存结束后才重新布防，避免因阈值附近波动反复增加 `vibrationCount`。

### 3.5 一般/严重威胁传递

`ImuData` 增加：

- `raw_timestamp_ns`
- `timestamp_fallback`
- `vibration_accel_rms`
- `vibration_gyro_rms`
- `severe_vibration_alert`

`AlertManager` 不再在相机帧上用单点绝对幅值重新判定，而是直接消费 IMU 回调已确认的一般/严重振动标志。

### 3.6 四相机同步组

同一同步组中按以下优先级保留 IMU 快照：

```text
冲击/严重振动 > 一般振动 > 无振动
```

等级相同时保留 Gyro RMS 更大的样本。

## 4. IMU 标定处理说明

项目已有偏置和缩放补偿，从 `param/calib/imu/imu-intrinsic.json` 读取，公式为：

```text
corrected = (raw - bias) / (1 + scale)
```

本次未实施动态偏置和动态缩放更新，原因如下：

- 高通 RMS 已能消除固定偏置和慢漂移，振动告警对直流偏置不敏感。
- 振动期间动态学习偏置可能把真实振动学习掉，导致漏报。
- 缩放系数无法靠单一静止姿态可观测，需要六面体/多姿态或已知角速度基准标定。

两个静止包中，原始陀螺仪均值模长约为 `0.00018~0.00022 rad/s`，按当前 JSON 和公式补偿后残余约为 `0.00110 rad/s`。建议先确认 `/sensor/imu` 是否已在驱动层标定，以及 JSON bias/scale 的定义，避免重复补偿。

## 6. 接口与配置兼容性

### 6.1 C++ 接口变化

`ImuSubscriber` 构造方式由：

```cpp
ImuSubscriber(float accel_threshold, float gyro_threshold)
```

改为：

```cpp
ImuSubscriber(const ImuDetectionConfig& config)
```

项目内部调用点已全部同步修改。如有项目外部代码直接构造 `ImuSubscriber`，需要适配新接口。

### 6.2 旧阈值

`imu_accel_threshold`、`imu_gyro_threshold` 等旧字段暂时保留，以维持配置文件兼容；IMU 振动分类已改用新的高通 RMS 字段。

### 6.3 回放 ODD

`prepare_bag_replay_env.sh` 产生的 `config.bag_replay.yaml` 会强制满足离线哨兵 ODD，用于低 SOC、缺少钥匙距离或缺少用户开启信号的数据包。该改动仅作用于生成的回放配置，不改变生产 `build/config.yaml` 的 ODD 默认值。

## 9. 回退说明

如需回退 IMU 算法，需成组回退以下内容，不建议只回退单个文件：

1. `ImuDetectionConfig` 和 `ImuData` 新字段。
2. `ImuSubscriber` 构造接口及高通/RMS 检测。
3. `SentinelConfig` 和 YAML 新配置。
4. `AlertManager` 基于振动标志的分类。
5. 四相机同步组的 IMU 优先级保留。

回退后必须重新编译，并重跑摇晃包和至少一个静止对照包。
