# IMU 哨兵模式修复与回放实验报告

- 实验日期：2026-08-04
- 项目目录：`/home/zhangweiyang/文档/0804/sentinel-fortress-master`
- 结论：本次修复通过。摇晃包能触发 IMU 事件，并完成 `ACTIVE -> WARNING -> ALARM` 哨兵状态闭环；5 m、15 m 和静止对照包未产生 IMU 误报。

## 1. 原问题

1. 旧算法直接将单帧水平加速度/角速度绝对值与 `2.0 m/s² / 0.5 rad/s` 比较。实测摇晃包角速度 RMS 仅约 `0.0027~0.0079 rad/s`，阈值高两个数量级，因此无法报警。
2. `actualTimeNs` 存在周期性回退：0801 包约回退 `100~110 ms`，0724 包约回退 `60 ms`。旧锁存直接依赖该时间，时长不可靠。
3. IMU 虽为约 100 Hz，但威胁评估只在相机同步组完成时执行；同步组内原来由最后一路相机覆盖 `pending.imu`，可能丢失前面相机捕获的振动快照。
4. 旧算法计算了 `delta_accel_xy`，实际冲击判断却使用三轴 `delta_accel`，姿态/Z 轴重力变化可带来误判风险。
5. `stop()` 释放 IMU 订阅器后才读取统计，导致日志末尾总是显示 `vibrations=0`。

## 2. 修改内容

- IMU 100 Hz 回调内使用一阶 2 Hz 高通去除重力、零偏和慢姿态变化。
- 计算 500 ms 三轴高通能量 RMS，要求超阈持续 300 ms，再锁存 3000 ms。
- 一般振动阈值：`accel RMS >= 0.14 m/s²`，或 `gyro RMS >= 0.0015 rad/s` 且 `accel RMS >= 0.04 m/s²`。
- 严重振动阈值：`accel RMS >= 0.20 m/s²`，或 `gyro RMS >= 0.0040 rad/s` 且 `accel RMS >= 0.04 m/s²`。
- 事件在锁存结束前不重新布防，避免同一段连续摇晃因 RMS 跨阈反复计数。
- 对不在 2~30 ms 范围的 `actualTimeNs` 相邻间隔按 10 ms 合成单调时钟，同时保留原始时间和 fallback 诊断。
- 四相机同步组改为保留组内告警等级最高/角速度 RMS 最大的 IMU 快照。
- 冲击加速度判定改为真正使用 XY 平面帧间差。
- 运行统计改为在 `stop()` 前保存。
- 增加 TensorRT 8/10 API 兼容，回放构建脚本在 x86 上使用系统 FFmpeg，并为回放配置强制满足哨兵 ODD。生产 `build/config.yaml` 的 ODD 默认值未改。

## 6. 局限与后续建议

- 当前阈值由 5 个包标定，已能分开本次摇晃与静止机械振动，但尚不是批量车型的最终量产阈值。
- 需补充拉门把手、踢碰车身、砸窗、大车经过、强风和坡道姿态变化等带标签数据，分别标定一般与严重阈值。
- `actualTimeNs` 的源头回退仍应在传感器/时钟同步链路排查；本次 fallback 保证了告警算法不再被回退破坏，但不代替底层时钟修复。
